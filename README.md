# Web2APK Pro

Package a plain **HTML/CSS/JavaScript** project (no framework, no build step) into an installable Android APK that
renders it in a native Kotlin `WebView`. Written for Kali Linux (Bash + Python 3 CLI), no Android Studio, no GUI.

```
web2apk init my-web-app          # starter project
web2apk build ./my-web-app       # debug APK
web2apk build ./my-web-app --release --keystore ~/keys/release.p12 --key-alias mykey
```

## 2. Architecture

```
web2apk build ./site
   1 check toolchain (Java>=17, SDK, platform android-35, build-tools, Gradle)
   2 read web project  -> pick web root + entry, skip hidden/secret/symlink files, static HTML warnings
   3 generate Android project from templates into <site>/.web2apk/build/android  (incremental, write-if-changed)
   4 Gradle assembleDebug|assembleRelease  (system Gradle, or a generated wrapper)
   5 release only: zipalign -> apksigner sign -> apksigner verify
   -> <site>/.web2apk/out/<app>-<version>-<debug|release>.apk
```

```
src/web2apk/  cli.py  builder.py  config.py  project.py  android_sdk.py  signing.py
              validation.py  diagnostics.py  utils.py
              templates/android/...   (Kotlin WebView app, Gradle Kotlin DSL; *.tpl use @@PLACEHOLDERS@@)
              templates/starter/...   (used by `web2apk init`)
tests/  examples/hello-web/  setup-kali.sh  uninstall.sh  web2apk (launcher)
```
Templates live inside the package (not a top-level `templates/`) so a pip install carries them.

### Version constraints
| Component | Pinned | Why |
|---|---|---|
| Android Gradle Plugin | 8.7.3 | needs Gradle >= 8.9 and JDK 17+; supports compileSdk 35; works with Kotlin 2.0.21 |
| Gradle | your 8.14.3 (system) | AGP 8.x is not compatible with Gradle 9 |
| Kotlin | 2.0.21 | as requested |
| JDK | 21 (17+ accepted) | Kotlin/Java target is 17 |
| compileSdk | 35 | androidx libs used need compileSdk 34+; **targetSdk is independent** (`--target-sdk 33/34/35`) |
| androidx | appcompat 1.7.0, webkit 1.11.0, core-splashscreen 1.0.1 | |

Override pins: `web2apk config set agp_version 8.9.1` (the compatibility table is consulted), `kotlin_version`, `compile_sdk`.

### Gradle wrapper: why and how
A global Gradle can build an Android project only if its version is inside the range the Android Gradle Plugin supports.
`--gradle-mode auto` (default) therefore: uses system Gradle when compatible (your 8.14.3 is), otherwise creates a
**wrapper** pinned to `gradle_version`. The wrapper is generated by running `gradle wrapper` in an empty scratch project
(so it doesn't need AGP to resolve), cached in `~/.cache/web2apk/wrapper-<ver>/` and copied into the generated project as
`gradlew`. Its first run downloads that Gradle distribution (~130 MB) unless it is already in `~/.gradle`.
Force with `--gradle-mode system|wrapper`.

## 3. Install (Kali)

```bash
sudo apt update && sudo apt install -y python3 python3-venv openjdk-21-jdk   # only if missing
tar xzf web2apk-pro.tar.gz && cd web2apk-pro
./setup-kali.sh            # user-level: venv in ~/.local/share/web2apk-pro, link in ~/.local/bin (no sudo)
./setup-kali.sh --icons    # also installs Pillow (needed only for custom --icon)
web2apk doctor
```
Without installing: `./web2apk --help` runs from the checkout.

The installer does not install or reinstall SDK packages. If `doctor` reports a missing piece (SDK at `/opt/android-sdk`
is detected automatically; also `ANDROID_HOME`, `ANDROID_SDK_ROOT`, `~/Android/Sdk`):
```bash
sdkmanager --sdk_root=/opt/android-sdk "platforms;android-35" "build-tools;35.0.0" "platform-tools"
sdkmanager --sdk_root=/opt/android-sdk --licenses
```
(Use elevated rights only if `/opt/android-sdk` isn't writable by you; Web2APK never needs sudo for builds.)
Custom locations: `web2apk config set sdk_path|java_home|gradle_path <path>`.

### Uninstall
```bash
./uninstall.sh            # removes only the venv and the ~/.local/bin/web2apk link it created
./uninstall.sh --purge    # also ~/.config/web2apk and ~/.cache/web2apk
web2apk clean ./site --all --logs   # per-project .web2apk build/log/out folders
```
Never touched: SDK, Java, Gradle, your projects, keystores.

## 4. Commands

| Command | Purpose |
|---|---|
| `web2apk init DIR [--name N] [--package P]` | starter project (refuses non-empty dirs) |
| `web2apk build [DIR] [options]` | build APK (see below) |
| `web2apk doctor` | check Java, keytool, SDK, platforms, build-tools, adb, licences, Gradle/AGP compatibility, Pillow, signing setup |
| `web2apk config [show\|get\|set\|unset\|path]` | global defaults, e.g. `config set defaults.orientation portrait` |
| `web2apk keystore create PATH --alias A [--dname ...]` | new PKCS12 keystore; never overwrites; chmod 600 |
| `web2apk verify app.apk` | `apksigner verify --print-certs` |
| `web2apk clean [DIR] [--logs] [--all] [--dry-run]` | removes only `.web2apk/build` (marker-checked), optionally logs/out |
| `web2apk version` | version |

Global flags: `-q/--quiet`, `-v/--verbose`, `--no-color`, `--no-interaction`. Build: `--dry-run`, `--offline`, `--force`,
`--output-dir`, `--gradle-mode`, plus every config key as a flag (`--name --package --icon --min-sdk --target-sdk --version-name
--version-code --entry --web-root --orientation --status-bar-color --splash-color --[no-]fullscreen --[no-]internet
--[no-]uploads --[no-]downloads --[no-]js-bridge --[no-]debug-webview`).

**Exit codes**: 0 ok, 1 unexpected, 2 usage, 3 config/project, 4 toolchain, 5 build, 6 signing, 7 needed interaction.
Status goes to stderr; with a successful build **stdout contains only the APK path**: `apk=$(web2apk build . -q --no-interaction)`.
If app name / package are missing, interactive runs prompt (and offer to save to `web2apk.json`); with `--no-interaction` defaults are derived and a warning is printed.

## 5. Configuration (`web2apk.json` in the project dir)

```json
{
  "app_name": "My Web App", "package_id": "com.example.mywebapp",
  "version_name": "1.0.0", "version_code": 1,
  "entry_point": "index.html", "web_root": "auto",
  "min_sdk": 23, "target_sdk": 35, "orientation": "portrait",
  "internet_access": false, "allow_cleartext": false, "allowed_origins": [],
  "fullscreen": false, "allow_file_uploads": true, "allow_downloads": false,
  "permissions": [], "js_bridge": false, "debug_webview": false,
  "status_bar_color": "#1F2937", "splash_color": "#111827", "icon": "icon.png"
}
```
Precedence: command line > project file > global `defaults` > built-in. Unknown keys and wrong types are errors (with "did you mean").
`web2apk.json` itself is never packaged into the APK.

* **web_root/entry_point**: `auto` looks for `index.html` in `.`, then `public/`, `assets/`, `www/`. Set `web_root: "public"` or `entry_point: "pages/home.html"` explicitly. Multi-page navigation works (relative links).
* **internet_access=false** (default) means the manifest declares **no INTERNET permission**: a true offline app.
* **allowed_origins**: hosts (`example.com`, `*.example.com`) allowed to load *inside* the app (needs `internet_access`). All other links open in the system browser.
* **permissions**: `camera`, `microphone`, `location`; only the ones listed are declared in the manifest and honoured, and only for trusted origins.
* **orientation**: `auto|portrait|landscape`. **icon**: PNG/JPEG/WebP (needs Pillow); default is a generated placeholder icon. Splash uses the icon on `splash_color` (androidx core-splashscreen, all API levels).
* Pages should include `<meta name="viewport" content="width=device-width, initial-scale=1">`; the tool warns if missing.

## 6. Example, build, install on a phone

```bash
web2apk build examples/hello-web           # -> examples/hello-web/.web2apk/out/hello-web-1.0.0-debug.apk
```
On the phone: enable Developer options → USB debugging, connect, accept the RSA prompt.
```bash
adb devices                                # must list the phone as "device"
adb install -r examples/hello-web/.web2apk/out/hello-web-1.0.0-debug.apk
adb shell monkey -p com.example.helloweb 1 # launch (or tap the icon)
adb logcat | grep -i chromium              # WebView console output (debug builds)
```
No adb? `sudo apt install adb`, or copy the APK to the phone and allow "install unknown apps" for your file manager. Uninstall: `adb uninstall com.example.helloweb`.
To inspect pages live: build with `--debug-webview`, open `chrome://inspect` on the desktop.

## 7. Debug vs release APK

* **Debug** (`web2apk build .`): signed automatically with the shared Android *debug* key, debuggable. For testing on your own devices. Not for distribution or stores.
* **Release** (`--release`): not debuggable, signed with **your** key. This key is your app's identity: updates must use the same key.

```bash
# one-time: create a keystore (prompts for a password with no echo)
web2apk keystore create ~/keys/release.p12 --alias mykey --dname "CN=Your Name, O=You, C=US"
# build + sign + verify (prompts for the password)
web2apk build ./my-web-app --release --keystore ~/keys/release.p12 --key-alias mykey
# CI (no prompts): secrets only via environment
export WEB2APK_KEYSTORE=~/keys/release.p12 WEB2APK_KEY_ALIAS=mykey WEB2APK_KEYSTORE_PASSWORD=...
web2apk build ./my-web-app --release --no-interaction -q
web2apk verify ./my-web-app/.web2apk/out/my-web-app-1.0.0-release.apk
```
Signing happens *after* Gradle, via `zipalign` + `apksigner`, so no keystore path or password ever enters generated project files.
Passwords reach keytool/apksigner only through child-process environment variables (`env:` / `-storepass:env`), never argv, logs or shell history
(avoid typing `WEB2APK_KEYSTORE_PASSWORD=...` inline in an interactive shell; use a CI secret store or `read -s`).
Existing keystores and release APKs are never overwritten (`--force` is required for the APK). **Back up the keystore and its password.**

## 8. Security model

* **Build time**: project JavaScript/shell scripts are never executed; only text-scanned. Asset paths are resolved inside the web root (`..`, absolute paths and symlink escapes rejected; symlinks are skipped). Hidden files (`.env`, `.git`), `node_modules`, and key-like files (`*.keystore, *.jks, *.p12, *.pem, *.key`) are not packaged. `clean` deletes only a marker-verified directory under `.web2apk`. No `sudo` anywhere.
* **Runtime**: pages load from `https://appassets.androidplatform.net/assets/www/...` through `WebViewAssetLoader` (no `file://`; `allowFileAccess=false`). JavaScript is enabled (required for your app); that means any script in your pages runs with the app's WebView privileges, so don't embed untrusted third-party scripts. Mixed content blocked, cleartext off unless `allow_cleartext`, TLS errors are never bypassed. Top-level navigation is limited to the app origin plus `allowed_origins`; everything else goes to the system browser; only http(s)/mailto/tel are forwarded, other schemes are dropped. `allowBackup=false`. WebView debugging only works in debug builds *and* with `debug_webview`.
* **Enabling `internet_access`** lets your pages (and any script they include) make network requests. `allowed_origins` limits *navigation*, not subresource requests; add a `Content-Security-Policy` meta tag to your pages to constrain those.
* **JS bridge** (`js_bridge: true`): implemented with `WebViewCompat.addWebMessageListener` restricted to the app's own asset origin and main frame, not `addJavascriptInterface`, so remote iframes/pages can't call it. Methods are fixed and narrow: `getAppInfo`, `isOnline`, `showToast` (text 1-200 chars); inputs are validated; messages over 4 KB are ignored. Usage: see `examples/hello-web/script.js`.
* **Downloads** (`allow_downloads`, needs internet): shown in a confirmation dialog; https only (http if cleartext allowed). `blob:` and local-asset downloads aren't supported.
* **File uploads**: system file chooser; no storage permission needed.

## 9. Features not done / known limits
Camera capture via `<input capture>`, `blob:` downloads, push notifications, deep links, and subresource allow-listing are not implemented. Custom icons are not adaptive icons. R8/minify is off. Lint is skipped for release builds to avoid extra downloads. The first build needs network access to Google Maven/Maven Central; later builds can use `--offline`.
